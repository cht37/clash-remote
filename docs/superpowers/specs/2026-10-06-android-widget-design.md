# Android 桌面微件设计

日期：2026-10-06。

## 用户已确认的目标与原型

用户要求新增安卓桌面微件，用于快速控制代理模式和节点选择。用户已查看原型，并确认“满足需求，继续”。

原型采用现有松绿配色：桌面卡片包含 Clash Remote 标识、路由器名称、更新时间、规则 / 全局 / 直连三个按钮、当前节点和刷新按钮。点击当前节点打开可搜索的节点选择面板，点选节点直接提交。

## 范围和实现选择

- 一个可调整大小的微件，默认目标 4×2；具体桌面网格由 Launcher 决定，布局按 dp 适配，保证主要操作可用。
- 延续最低 Android 8.0、compile / target SDK 36。
- 使用原生 AppWidgetProvider、RemoteViews 与 XML 布局承载桌面卡片；独立 Compose Activity 承载微件配置和节点选择面板。
- 微件只展示控制快照。更新由添加微件、手动刷新、控制操作和主应用相关配置 / 控制变更触发，不进行后台实时流量连接或高频轮询。
- 使用 WorkManager 承载一次性后台网络任务，避免在 BroadcastReceiver 生命周期内等待网络。
- 复用 ProfileStore、OkHttpClashApi、现有 API 数据模型和错误映射。新增桌面控制逻辑独立于依赖前台生命周期的 RemoteController。
- 微件沿用用户选择的应用配色，并提供系统深浅色资源。此次不增加测速、订阅管理、服务启停或 VPN 功能。

与直接把节点列表放进微件相比，独立选择面板可以保留搜索、较大的触摸目标和紧凑的桌面卡片。与完全使用 Glance 相比，RemoteViews 不要求把应用 Compose 组件迁移成另一套组件，且满足这张固定控制卡片的需求。

## 用户交互

### 添加与配置

在系统微件列表中显示“Clash Remote”。添加时进入配置页，从路由器返回的 Selector 策略组中选择一个组绑定到该微件；保留 API 顺序。每个微件可选择不同策略组，路由器配置仍复用主应用保存的单个配置。

未保存路由器时显示“请先配置路由器”，提供进入主应用设置的入口；不创建默认在线状态。路由器不可达时显示错误和重试入口，允许用户取消添加。配置 Activity 默认返回 RESULT_CANCELED，只有组绑定持久化并提交初始 RemoteViews 后才返回 RESULT_OK 和 appWidgetId。

已放置微件可通过卡片中的策略组入口重新配置，不依赖 Android 12+ 才支持的系统重配置入口。删除微件时清除该 ID 的绑定与状态。

### 模式切换

规则 / 全局 / 直连分别映射 rule / global / direct。点击按钮立即显示处理中并禁用重复提交。PATCH /configs 成功后回读 GET /configs，并刷新所有微件上的模式，因为模式属于路由器全局配置。

只在收到回读结果后更新选中按钮。写操作失败保留此前快照，并显示错误；如果写入成功但回读失败，显示“操作可能已生效，请刷新确认”，不能显示已确认成功。无已验证快照时不默认高亮规则模式。

### 节点选择

点击当前节点通过明确的 Activity PendingIntent 打开底部面板。面板显示组名、路由器名称、搜索框、节点列表与当前节点标记。只展示绑定组 all 中的成员，保留原顺序，支持中文、空格、斜线和 emoji。搜索不区分大小写。

打开面板重新获取组信息，避免仅凭缓存提交已删除的节点。提交前确认组仍是 Selector、节点仍属于该组。点击节点立即提交；提交期间禁用重复操作，成功回读 GET /proxies 后更新微件并关闭面板。失败保留面板、当前项与搜索输入，显示错误并允许重试。点击关闭、返回或面板外区域可以取消浏览。

若绑定组已删除或类型变成非 Selector，显示“策略组不可用，请重新选择”，保留重新配置入口，不自动切换到另一个组。选择面板不建立流量连接，不加载连接列表。

### 刷新与进入主应用

右上角刷新获取 /configs 和 /proxies；成功后更新模式、当前节点和最后成功同步时间。点击应用标题进入主应用；未配置状态的入口直接定位设置。

刷新失败保留最后确认的控制快照，并标记获取失败。更新时间显示明确的时刻（例如“更新于 09:41”），避免进程退出后一直显示“刚刚更新”。状态点表示最近同步结果，不宣称持续在线。

## 组件职责

| 组件 | 职责与边界 |
| --- | --- |
| 桌面控制模型 / 客户端（core） | 一次性读取控制快照、验证模式与组成员、执行写入及回读；可注入 ClashApi 替身进行 JVM 测试 |
| WidgetStore（app） | 私有持久化每个 appWidgetId 的组绑定、最后确认快照、同步时间、配置代次和可读错误；不保存 secret |
| ProxyWidgetProvider（app） | 接收系统微件更新、删除、大小变化以及应用明确的模式 / 刷新事件；只调度任务和渲染，不阻塞等待 API |
| WidgetWorker / 调度器（app） | 加载加密配置、执行一次性网络请求、串行化桌面写操作、拒绝过期操作，并更新 RemoteViews |
| WidgetRenderer（app） | 根据持久快照与状态生成可操作 RemoteViews，设置独立明确的 PendingIntent |
| WidgetConfigActivity（app） | 校验微件 ID、读取可手选策略组、保存绑定及完成系统配置协议 |
| WidgetNodeActivity / ViewModel（app） | 底部选择面板、搜索、加载、提交与失败反馈；通过同一桌面控制边界发起操作 |
| 主应用集成 | 配置保存 / 清除、配色变更及已确认模式 / 节点变更后通知微件同步；支持从微件定位设置 |

新增类保持职责独立，不把微件生命周期塞进现有 RemoteController。桌面卡片资源、系统 metadata 和 Activity 注册集中在 app 模块。

## 数据与任务生命周期

1. 每次桌面事件携带微件 ID、操作类型、必要的模式 / 组 / 节点，以及绑定代次。Intent 和 WorkManager Data 不包含 secret 或路由器凭据。
2. 调度器验证 ID 属于本应用的已配置微件，确认请求与当前绑定和路由器配置代次一致。桌面控制请求串行执行，处理中拒绝重复提交。
3. 网络任务从 ProfileStore 读取当前配置，通过 OkHttpClashApi 发起请求；在 finally 中关闭客户端。任务有明确超时，不进行无限重试，写操作失败不自动重放。
4. 结果写回前再次核对微件绑定与路由器配置代次。旧路由器、已删除微件或旧绑定的结果不得覆盖当前状态。已经发送到旧路由器的请求无法撤回，其结果丢弃。
5. 同一路由器的模式变化同步所有微件；节点变化更新相应组快照。主应用返回前台时继续使用既有刷新流程获取实际状态。
6. 配置保存 / 清除后使旧缓存和任务失效，并重新渲染所有微件。清除配置后禁用控制，显示设置入口；不能继续使用旧密钥。重新保存配置后重新校验策略组。
7. 进程重建时从持久配置与快照恢复卡片。缓存中的处理中状态不能永久禁用微件；没有存活任务时恢复为待刷新。

## 平台和信息保护

AppWidgetProvider 按系统微件协议声明 metadata 与 APPWIDGET_UPDATE。自定义控制事件使用明确组件和 immutable PendingIntent，并为每个微件与操作设置不同身份，避免 Intent extras 被其他按钮覆盖。

节点面板由 PendingIntent.getActivity 直接启动，避免通过后台广播再启动 Activity。Activity 的微件 ID、配置代次和绑定全部由应用校验。外部可见配置入口不信任传入组名或节点名。

secret 继续由 Android Keystore AES-GCM 加密配置保存；禁止加入桌面布局、工作参数、日志、缓存或错误信息。API 地址与节点路径编码沿用现有客户端，HTTPS 继续使用系统证书验证。

## 错误与视觉状态

区分未配置、等待首次同步、处理中、最近同步成功、同步失败和策略组不可用。控制按钮在未配置或提交期间不可操作，刷新 / 重新配置入口按状态保留。

401 / 403、超时、TLS 与接口不兼容错误沿用现有中文说明。配置解密失败引导重新配置，不以空 secret 继续请求。错误文案不暴露密钥；失败不改变最后确认的选中项。

布局保持原型的圆角卡片、三个同宽模式按钮及节点行。较长路由器、组与节点名称通过省略或有限换行处理；交互触摸目标以 48dp 为基准，允许缩放桌面卡片，深浅色保证选中项和错误文字可辨认。
